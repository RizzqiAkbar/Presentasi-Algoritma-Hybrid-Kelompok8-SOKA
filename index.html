01 / Landasan literaturHeuristik × metaheuristik

Algoritma Hybrid ACO + Max-Min dan GA + Min-Min

Analisis Perbandingan Penjadwalan Task pada Cloud Computing

Heuristik menyusun jadwal awal. Hasilnya menjadi heuristic seed untuk pencarian metaheuristik. Urutan eksekusinya adalah Max-Min + ACO dan Min-Min + GA.

Eksperimen membandingkan kedua hybrid pada infrastruktur heterogen dengan dataset Google Cluster Jobs (GoCJ).

Alur penjadwalan hybrid

Objektif kedua optimizer: minimum makespan. DoI dan utilisasi adalah metrik evaluasi, bukan kriteria tie-break.

02 / Cara kerja algoritmaHeuristik → feromon → eksplorasi

Max-Min + ACO

Max-Min menyusun jadwal awal. ACO memakai jadwal tersebut sebagai seed feromon untuk mengeksplorasi alokasi lain.

Rumus dan parameter Max-Min + ACO

Informasi lokal

ETᵢⱼ = Length(Tᵢ) / MIPS(VMⱼ)
CTᵢⱼ = ETᵢⱼ + RTⱼ
ηᵢⱼ = 1 / (ETᵢⱼ + 10⁻⁶)

Probabilitas & update

Pᵢⱼ = τᵢⱼᵅ ηᵢⱼᵝ / Σₖ τᵢₖᵅ ηᵢₖᵝ
τ ← max(0,01; (1 − ρ)τ)
τᵢ,best ← τᵢ,best + Q / MSbest

Default terverifikasi

25 semut · 50 iterasi
α = 1 · β = 2 · ρ = 0,2 · Q = 100
Seed: 3,0; jalur lain: 1,0

Parameter berasal dari Hybrid.java. Pada benchmark tercatat, ACO memakai 60,9–354,0 ms dan utilisasi 98,9–99,9%. Itu observasi eksperimen, bukan jaminan setiap skenario.

03 / Cara kerja algoritmaHeuristik → kromosom → evolusi

Min-Min + GA

Min-Min menyusun jadwal awal. GA menjadikannya kromosom pertama, lalu membentuk kandidat baru melalui seleksi, crossover dan mutasi.

Rumus dan parameter Min-Min + GA

Representasi

Posisi gen = task.
Nilai gen = VM tujuan.
MS(K) = maxⱼ Σᵢ∈Kⱼ ETᵢⱼ

Fitness & variasi

Fitness(K) = 1 / MS(K)
Tournament k = 3
Single-point crossover, lalu mutasi gen

Default terverifikasi

30 kromosom · 50 generasi
P(crossover) = 0,8 · P(mutasi) = 0,05
Elit global disalin ke slot 0 generasi baru.

Pada benchmark tercatat, GA memakai 19,6–92,5 ms, DoI 0,069–0,271. Java memakai seed dinamis per dataset untuk infrastruktur yang sama; lab memakai seed numerik tetap dan PRNG browser yang berbeda.

Model simulasi, metrik, dan batas interpretasi

Simulasi penjadwalan di browser, bukan CloudSim. Semua task tersedia pada t = 0; satu task per VM pada satu waktu (space-shared), tanpa preemption, transfer jaringan, startup, deadline, atau kegagalan. Kapasitas host memvalidasi reservasi total MIPS. Host hanya mengatur placement dan visualisasi; menambah host tanpa mengubah VM tidak mempercepat task.

Model normal memakai ET = MI/MIPS. Matriks custom adalah estimasi independen dalam detik. Mapping heuristic menyimpan urutan konstruksi; timeline parsial mengikuti urutan itu. Timeline optimizer/final mengikuti ID task, seperti urutan submit pada broker Java. Makespan tidak berubah oleh urutan dalam model ini.

DoI = (beban maksimum − minimum) / (rata-rata + 10⁻⁹). Utilisasi = Σ beban / (makespan × jumlah VM + 10⁻⁹) × 100%. VM idle tetap dihitung. Metrik saat konstruksi bersifat proyeksi parsial. Perbaikan makespan tidak menjamin perbaikan DoI. Waktu komputasi browser mencakup pembuatan trace; tidak setara runtime Java.

ACO dan GA mempertahankan global best hanya jika makespan lebih kecil, tanpa tie-break DoI. Tampilan menampilkan sampel eksplorasi dan operasi; seluruh populasi tetap dihitung. Tidak ada jaminan optimum global atau perbaikan dari seed.
