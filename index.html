01 / Landasan literaturHeuristik × metaheuristik

Algoritma Hybrid ACO + Max-Min dan GA + Min-Min

Analisis Perbandingan Penjadwalan Task pada Cloud Computing

Heuristik menyusun jadwal awal. Hasilnya menjadi heuristic seed untuk pencarian metaheuristik. Urutan eksekusinya adalah Max-Min + ACO dan Min-Min + GA.

Eksperimen membandingkan kedua hybrid pada infrastruktur heterogen dengan dataset Google Cluster Jobs (GoCJ).

Alur penjadwalan hybrid

Objektif kedua optimizer: minimum makespan. DoI dan utilisasi adalah metrik evaluasi, bukan kriteria tie-break.

Landasan teori dari jurnal

IJAMTES · Desember 2018 · hlm. 32–42

Task Scheduling based on Advance Ant Colony Optimization and Particle Swarm Optimization with Machine learning in the cloud environment

Mrs. Nahla Ahmed Faraj & Prof. Ramesh Babu Inampudi. International Journal of Management, Technology And Engineering, Vol. 8, Issue XII.

Kutipan pendukung

“when larger task is assigned to a VM with low processing ability”

Cuplikan kalimat · halaman 33

Task besar pada VM lambat memerlukan waktu lebih panjang. Sebaliknya, task kecil yang memakai VM cepat dapat membuat task besar menunggu. Penjadwalan perlu mempertimbangkan ukuran task dan kemampuan VM.

“The main idea of ACO derives from the foraging behavior of ant colonies.”

Halaman 36

Feromon menyimpan jejak pencarian. Pada alokasi task–VM, probabilitas pemilihan memadukan feromon dan informasi heuristik; jejak kemudian diperbarui untuk mengarahkan pencarian solusi berikutnya (hlm. 36–37).

Relevansi untuk Max-Min + ACO

Paper ini mendukung dasar ACO dan pentingnya mencocokkan task dengan VM heterogen. Kelompok menerapkannya dengan jadwal Max-Min sebagai global best awal dan seed feromon, lalu memakai ACO untuk mencari jadwal dengan makespan lebih rendah.

Penelitian aslinya memakai kerangka MLCCAP yang melibatkan AACO, PSO dan Classifier Chains. Kombinasi seeding Max-Min, nilai τ = 3/1 serta parameter pencarian mengikuti implementasi Java kelompok.

Baca PDF jurnal · hlm. 32–42

IJDSN · 2009 · hlm. 62–63

Min-Min Chromosome Genetic Algorithm for Load Balancing in Grid Computing

Wanneng Shu & Jiangqing Wang. International Journal of Distributed Sensor Networks, Vol. 5. DOI: 10.1080/15501320802554976.

Kutipan pendukung

“The new algorithm not only retains the advantage of the Min-min algorithm but also achieves the good load balancing.”

Halaman 62

Min-Min Chromosome Genetic Algorithm (MCGA) menggabungkan Min-Min yang cepat dengan pencarian global GA. Min-Min cenderung menjadwalkan task kecil lebih dahulu, sedangkan GA membantu mengeksplorasi kombinasi alokasi lain.

Penulis melaporkan utilisasi dan keseimbangan beban yang lebih baik dibandingkan Min-Min dan GA pada pengujian mereka (hlm. 62–63). Temuan ini mendukung penggunaan solusi heuristik sebagai dasar pencarian hybrid.

Relevansi untuk Min-Min + GA

Kelompok mengadaptasi konsep MCGA dari grid computing ke penjadwalan cloud pada CloudSim. Jadwal Min-Min menjadi kromosom pertama, lalu GA menjalankan seleksi, crossover dan mutasi untuk mencari makespan yang lebih rendah.

Populasi 30, tournament selection, Pc 0,8, Pm 0,05 dan fitness 1/makespan mengikuti implementasi Java kelompok.

Dasar pendekatan hybrid

Heuristik batch-mode menyusun alokasi awal. Dalam implementasi kelompok, Max-Min memberi seed feromon ACO, sedangkan Min-Min memberi seed kromosom GA. Metaheuristik kemudian mengeksplorasi alternatif jadwal. Kualitas akhirnya dinilai dari workload, anggaran pencarian dan hasil benchmark.

Rujukan tambahan: Max-Min dan Enhanced ACO

M. R. Banupriya dan D. Francis Xavier Christopher membahas MMH untuk load balancing diikuti Enhanced ACO untuk resource allocation, termasuk VM migration/WSVM. IJISAE 12(1s), 258–270 (edisi 2024; terbit daring 2023), khususnya §3.3–3.4.

Efficient Load Balancing and Optimal Resource Allocation Using Max-Min Heuristic Approach and Enhanced Ant Colony Optimization Algorithm over Cloud Computing.

Rujukan ini mendukung kombinasi heuristik Max-Min dan ACO dalam kerangka yang lebih luas. Seeding dan parameter eksperimen kelompok mengikuti kode Java yang diuji pada benchmark.

02 / Cara kerja algoritmaHeuristik → feromon → eksplorasi

Max-Min + ACO

Max-Min menyusun jadwal awal. ACO memakai jadwal tersebut sebagai seed feromon untuk mengeksplorasi alokasi lain.

Rumus dan parameter Max-Min + ACO

Informasi lokal

ETᵢⱼ = Length(Tᵢ) / MIPS(VMⱼ)
CTᵢⱼ = ETᵢⱼ + RTⱼ
ηᵢⱼ = 1 / (ETᵢⱼ + 10⁻⁶)

Probabilitas & update

Pᵢⱼ = τᵢⱼᵅ ηᵢⱼᵝ / Σₖ τᵢₖᵅ ηᵢₖᵝ
τ ← max(0,01; (1 − ρ)τ)
τᵢ,best ← τᵢ,best + Q / MSbest

Default terverifikasi

25 semut · 50 iterasi
α = 1 · β = 2 · ρ = 0,2 · Q = 100
Seed: 3,0; jalur lain: 1,0

Parameter berasal dari Hybrid.java. Pada benchmark tercatat, ACO memakai 60,9–354,0 ms dan utilisasi 98,9–99,9%. Itu observasi eksperimen, bukan jaminan setiap skenario.

03 / Cara kerja algoritmaHeuristik → kromosom → evolusi

Min-Min + GA

Min-Min menyusun jadwal awal. GA menjadikannya kromosom pertama, lalu membentuk kandidat baru melalui seleksi, crossover dan mutasi.

Rumus dan parameter Min-Min + GA

Representasi

Posisi gen = task.
Nilai gen = VM tujuan.
MS(K) = maxⱼ Σᵢ∈Kⱼ ETᵢⱼ

Fitness & variasi

Fitness(K) = 1 / MS(K)
Tournament k = 3
Single-point crossover, lalu mutasi gen

Default terverifikasi

30 kromosom · 50 generasi
P(crossover) = 0,8 · P(mutasi) = 0,05
Elit global disalin ke slot 0 generasi baru.

Pada benchmark tercatat, GA memakai 19,6–92,5 ms, DoI 0,069–0,271. Java memakai seed dinamis per dataset untuk infrastruktur yang sama; lab memakai seed numerik tetap dan PRNG browser yang berbeda.

Model simulasi, metrik, dan batas interpretasi

Simulasi penjadwalan di browser, bukan CloudSim. Semua task tersedia pada t = 0; satu task per VM pada satu waktu (space-shared), tanpa preemption, transfer jaringan, startup, deadline, atau kegagalan. Kapasitas host memvalidasi reservasi total MIPS. Host hanya mengatur placement dan visualisasi; menambah host tanpa mengubah VM tidak mempercepat task.

Model normal memakai ET = MI/MIPS. Matriks custom adalah estimasi independen dalam detik. Mapping heuristic menyimpan urutan konstruksi; timeline parsial mengikuti urutan itu. Timeline optimizer/final mengikuti ID task, seperti urutan submit pada broker Java. Makespan tidak berubah oleh urutan dalam model ini.

DoI = (beban maksimum − minimum) / (rata-rata + 10⁻⁹). Utilisasi = Σ beban / (makespan × jumlah VM + 10⁻⁹) × 100%. VM idle tetap dihitung. Metrik saat konstruksi bersifat proyeksi parsial. Perbaikan makespan tidak menjamin perbaikan DoI. Waktu komputasi browser mencakup pembuatan trace; tidak setara runtime Java.

ACO dan GA mempertahankan global best hanya jika makespan lebih kecil, tanpa tie-break DoI. Tampilan menampilkan sampel eksplorasi dan operasi; seluruh populasi tetap dihitung. Tidak ada jaminan optimum global atau perbaikan dari seed.

Mengapa ACO murni berbeda dari hybrid?

Hybrid: Max-Min menjadi global best awal, τ = 3 pada pasangan seed dan 1 pada lainnya; visibility memakai 1/(ETC + 10⁻⁶). Deposit hanya ke global best, Q = 100; batas bawah τ = 0,01.

ACO tugas sebelumnya: τ awal seragam 1. Visibility memakai prediksi completion time yang diperbarui saat kandidat dibangun. Deposit iteration-best dan global-best berbobot 0,5 memakai Q = total MI/kapasitas; τ dibatasi 0,01–10. Perbedaannya lebih luas daripada seeding.

GWO: satu serigala adalah satu jadwal lengkap. Alpha, beta dan delta memandu pembaruan posisi kontinu; indeks VM diperoleh dengan floor dan clamp. Global best disimpan terpisah. Implementasi asli MetaScheduler dipakai tanpa menulis simulator interaktif GWO baru.
